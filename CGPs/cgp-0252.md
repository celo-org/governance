# Overview

This proposal is a proxy governance proposal that mirrors Mento Governance Proposal 18 (MGP-18). As part of the ongoing coordination between the Celo and Mento communities, Celo token holders can direct how the Celo Community Fund's MENTO allocation votes in Mento Governance.

MGP-18 starts the deprecation of Mento V2. It changes the trading limits for the ten USDm/FX exchanges that remain on V2. It also describes a separate migration multisig operation that will destroy six legacy V2 exchanges.

# Summary

MGP-18 keeps the following USDm/FX exchanges active on Mento V2:

- USDm/AUDm
- USDm/CADm
- USDm/ZARm
- USDm/COPm
- USDm/BRLm
- USDm/PHPm
- USDm/GHSm
- USDm/NGNm
- USDm/KESm
- USDm/XOFm

For each exchange, MGP-18 replaces the current 5-minute, 1-day, and global Broker trading limits with a global-only limit on both assets. The FX-token limit equals 110% of its total supply when the proposal is created. The USDm limit equals 110% of that supply's USD value at the current oracle rate. Each limit is reset before the new limit is set. This results in 40 Mento governance calls across the ten exchanges.

The limits apply to Broker-mediated net flows. They do not create a total supply cap and do not change other authorized minting paths.

Separately from the MGP-18 calldata, the migration multisig plans to destroy these six V2 exchanges:

- USDm/USDC
- USDm/axlUSDC
- USDm/USDT
- USDm/CELO
- USDm/EURm
- EURm/axlEUROC

This operation does not affect Mento V3 deployments.

This CGP only directs the Celo Community Fund's proxy vote on MGP-18. It does not execute the 40 Broker calls or the separate migration multisig operation on Celo.

# Risks

- Limit sizing risk: The proposal fixes each limit when its calldata is created. Token supply and oracle rates can change before execution. The 10% buffer reduces this risk but does not remove it.
- Exit risk: A holder's ability to exit through the Broker also depends on supply growth, exchange-rate movement, oracle and circuit-breaker state, reserve liquidity, and contract availability.
- Trading-limit risk: Removing the 5-minute and 1-day limits can increase immediate Broker throughput for a pair when the new global limit is higher than an existing short-window limit.
- Execution risk: The 40 calls must execute in the intended order. An incorrect exchange ID, token address, limit, or call order could interrupt trading or change the intended exposure limit.
- Migration risk: Destroying the six legacy exchanges removes those V2 trading routes. The migration multisig operation is outside the MGP-18 calldata and requires separate execution.
